Platform Overview & Architecture

What Project M.I.R.A. is and why it exists.

Project M.I.R.A. (Middleware for Integration and Real-time Automation) is an enterprise-grade Integration Platform as a Service (iPaaS) engineered to bridge front-office CRM operations in Monday.com with back-office accounting ledgers in Xero.

In typical enterprise environments, sales teams manage client accounts, product line items, and deals in Monday.com boards, while the finance department prepares invoices, checks compliance, and reconciles payments in Xero. Manual data re-entry causes costly accounting mistakes, missing line items, duplicate contacts, and delayed invoicing.

Sub-Millisecond Speed

Transforms and validates batches at over 3,300 records per second with 0.15ms median latency.

Active Pre-Validation

Pydantic v2 schemas enforce finance-grade accuracy prior to submission, preventing dirty data ingestion.

Multi-Line Grouping

Intelligently bundles related line items by client company into single, reconciled multi-line invoices.

High-Level Data Pipeline
[Monday.com Boards] -> [M.I.R.A. Ingestion] -> [Pydantic Validator] -> [Dynamic Schema Mapper]
                                                  |
                                                  v
[Xero Cloud ERP]   <-- [OAuth 2.0 Dispatcher] <-- [Multi-Line Aggregator & VAT Engine]
        |
        +--> [Bidirectional Reconciliation] --> [Monday Status: 'Paid' / Invoiced]

Role-Based Access Control (RBAC) & Permissions

Comprehensive breakdown of platform roles and granular privileges.

M.I.R.A. enforces strict Role-Based Access Control (RBAC) across both the FastAPI REST interface and Flask Jinja2 web views. This ensures sensitive accounting credentials, user passwords, and schema mappings can only be altered by authorized personnel.

super_admin System Owner

Full System Authority

  • Manage all user accounts and roles
  • Create, edit, and toggle administrators
  • Configure Monday API tokens and Xero OAuth
  • Customize, map, and reset board schemas
  • Execute all synchronization batches
  • Full access to audit logs and telemetry
admin Administrator

Platform Management

  • Manage Platform Connectors (Monday and Xero)
  • Configure and edit Schema Mappings
  • Execute synchronizations with date filter
  • Manage Operator accounts (create, toggle active)
  • Cannot modify or delete Super Admin users
  • Access to system logs and documentation
user Operator

Operational Sync

  • Direct access to Sync Engine upon login
  • Trigger manual and batch synchronization
  • Select date filter and grouping options
  • Monitor real-time live terminal streaming
  • Read-only access to System Documentation
  • Protected from editing mappings or credentials

Guide: How to Obtain Xero Client ID & Client Secret

Step-by-step visual tutorial using the Xero Developer Portal (developer.xero.com).

To connect Project M.I.R.A. with your Xero accounting organization, you must register a developer application on Xero. This provides you with a Client ID (public identifier) and a Client Secret (private key) required for OAuth 2.0 authentication.

Xero Developer Portal Configuration Screenshot:
Step 1: Sign in to Xero Developer Portal

Navigate to developer.xero.com in your web browser. Click Log In in the top-right corner and enter your regular Xero credentials.

Step 2: Create a New Application

Click on My Apps in the navigation bar, then click the blue New App button in the upper-right area.

Step 3: Configure App Parameters
  • App name: Enter MIRA Integration (or any descriptive title for your organization).
  • Integration type: Select Web app.
  • Company or application URL: Enter your deployment URL, e.g. https://mira-software.onrender.com (or http://localhost:8000).
  • OAuth 2.0 redirect URI (Mandatory): Enter the exact authorization callback URL:
    https://mira-software.onrender.com/oauth/xero/callback
    (For local development, add http://localhost:8000/oauth/xero/callback as an additional redirect URI).

Check the box to agree to the Xero Developer Terms and Conditions, then click Create app.

Step 4: Copy the Client ID

On your app page, select the Configuration tab in the left sidebar. The Client id field contains a unique 36-character UUID string (e.g. 8f4c3a2b-1e09-4d6f-870a-3c2b1a094d6e). Click the Copy button next to it.

Step 5: Generate and Copy the Client Secret

Directly below the Client ID on the Configuration tab, locate the Client secrets section. Click the Generate a secret button.

Important Notice: Copy your secret immediately!

Xero only shows the full secret value once upon generation. If you navigate away or refresh the page, Xero masks the string permanently. Click the Copy button and store it safely.

Step 6: Authorize in M.I.R.A. Platform Connectors

Ensure your XERO_CLIENT_ID and XERO_CLIENT_SECRET are configured in M.I.R.A. (via environment variables or settings). Navigate to Platform Connectors and click Connect Xero Account OAuth. You will be redirected to Xero to grant organization permissions, and redirected back with a green Connected badge.

Step-by-Step: Running Synchronizations

Choosing directions, setting the date filter, executing runs, and reading live logs.

The Sync Engine (/sync) is the command center for data synchronization. Both administrators and operators have access to run batches and monitor telemetry.

M.I.R.A. Synchronization Control Panel Screenshot:
Direction 1

Xero to Monday.com (Default)

Ingests paid invoices, contacts, and account numbers from Xero. Matches Monday pulses by Account Number or Reference, updating their status to "Paid" or "Invoiced" and logging reconciliation audit comments.

Direction 2

Monday.com to Xero

Ingests closed deals and subitem rows from Monday. Transforms payloads into standard Xero Contact and Multi-Line Invoice entities, creating Draft or Authorised invoices in Xero with standard UK 20% VAT treatment.

Configurable Operational Parameters:

Date Selector Filter (since_date)

Allows syncing records created or modified on or after a specific calendar date. Leave blank to run an incremental sync (all pending records).

Target Account Code

Assigns the general ledger account code for generated invoice lines (e.g. 200 - Sales, 260 - Other Revenue).

Group Multiple Items by Company

When enabled, consolidates multiple deals or line items for the same client company into a single multi-line draft invoice instead of isolated single-line invoices.

Batch Count / Limit

Controls maximum number of items processed per batch run (e.g. 10, 50, 100, 500) to respect destination API rate limits.

Zero-Silent-Failure & Quarantine Architecture

How M.I.R.A. isolates bad records without breaking your integration pipeline.

Unlike commercial integration tools that silently drop records when encountering missing fields, M.I.R.A. implements a strict Zero-Silent-Failure Quarantine Policy:

Fault Isolation

If record #14 out of 100 has a missing company name or invalid number, only record #14 is quarantined. The remaining 99 records process smoothly without interruption.

Structured Diagnostics

Quarantined records are logged in SyncLog with exact field names, row IDs, and error diagnostics so administrators can rectify the data in Monday.com and re-sync.

User Management Console (Admins Only)

Creating users, assigning roles, and toggling active access.

Located at User Management (/admin/users), this view allows administrators to control who can access the integration middleware:

Key User Management Operations:
  • Create User: Enter email address, temporary password (min 6 characters), and select RBAC role (admin or user).
  • Super Admin Guard: Only existing super_admin users can create or edit other administrator accounts. Standard admin users can only provision user (operator) accounts.
  • Toggle Active Status: Click the status switch to immediately revoke or reactivate user access without deleting their historical audit records.
  • Password Security: All credentials are salted and hashed using PBKDF2 with SHA-256 (100,000 rounds).

Troubleshooting & Frequently Asked Questions (FAQ)

Resolutions for common setup errors and operational edge cases.

Q: What should I do if the Xero badge says "Token Expired"?

Xero access tokens expire after 30 minutes. M.I.R.A. automatically refreshes the token using the refresh token stored in your database during any sync run. If your refresh token has expired (after 60 days of inactivity), simply navigate to Platform Connectors and click "Connect Xero Account" to re-authorize.

Q: Where can I find my Monday.com Board IDs?

Open your board in Monday.com. Look at your browser's address bar. The URL follows this format: https://yourcompany.monday.com/boards/5101138223. The numerical digits at the end are your Board ID.

Q: How does the Date Selector filter work?

The "Sync records on or after" date selector filters records based on their creation or modification timestamp. If you choose 2026-09-01, only records dated on or after September 1st, 2026 will be processed. If left empty, all unreconciled records are evaluated.

Q: Can an Operator accidentally change schema mappings?

No. The Schema Mappings and Platform Connectors tabs are restricted to super_admin and admin roles. Operators only see the Sync Engine and this Documentation guide.

Q: How does M.I.R.A. prevent duplicate invoices in Xero?

M.I.R.A. includes an idempotency engine. Every generated invoice sets the Monday pulse ID or deal reference in Xero's Reference field. Before creating an invoice, M.I.R.A. checks if an invoice with that reference already exists.
